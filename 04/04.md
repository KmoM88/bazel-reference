# Chapter 4: The "Glue": Protobuf & gRPC
In a polyglot environment, ensuring that your C++ backend understands exactly what your Go or Python clients are sending is critical. Bazel solves this by treating Protocol Buffers (`.proto`) as the single source of truth and automatically generating the necessary code for every language.

## 4.1 Concept: Single Source of Truth & Defining Schemas
Instead of writing a C++ `struct` and then manually writing a matching Go `struct`, you define the data structure once in a `.proto` file.

- The `proto_library` rule: This is a language-agnostic rule. It tells Bazel: "Here is a schema file, and it depends on these other schema files." It does not generate C++ or Go code yet; it just defines the graph of protocol buffers.

### Practical: Defining the Schema
#### 1. Create the directory structure:

```bash
mkdir -p src/proto
```
#### 2. Create the Schema (`src/proto/greeter.proto`):

```protobuf
syntax = "proto3";

package greeter;

option go_package = "bazel-reference/04/src/proto";

// The Service definition
service Greeter {
  rpc SayHello (HelloRequest) returns (HelloReply) {}
}

// The Data definitions
message HelloRequest {
  string name = 1;
}

message HelloReply {
  string message = 1;
}
```
#### 3. Create the Bazel Target (src/proto/BUILD.bazel):

```
load("@rules_proto//proto:defs.bzl", "proto_library")

proto_library(
    name = "greeter_proto",
    srcs = ["greeter.proto"],
    visibility = ["//visibility:public"],
)
```
## 4.2 Code Generation Aspects
To turn that `.proto` file into usable code (like `greeter.pb.cc` or `greeter.pb.go`), we use language-specific rules that "wrap" the `proto_library`.

- C++ Bindings: We use `cc_proto_library`. For gRPC services, we also need a `cc_grpc_library` (often provided by the gRPC repository).
- Go Bindings: We use `go_proto_library` provided by `rules_go`. To generate gRPC code, we add the specific compiler plugin to the rule.
- Python Bindings: We use `py_proto_library` (via `rules_python` or native rules).

### Practical: Configuring Dependencies & Generation
First, we need to add the grpc and protobuf modules to our project so we have access to the compilers.

#### 1. Update MODULE.bazel:
Add these dependencies to your existing file.

```
# MODULE.bazel

# ... existing rules_cc, rules_go, etc ...

bazel_dep(name = "protobuf", version = "27.1")
bazel_dep(
	name = "grpc",
	version = "1.66.0",
	repo_mapping = {
        "com_github_grpc_grpc": "grpc",
    },
)
bazel_dep(name = "rules_proto", version = "6.0.0")

# Go-specific proto setup is handled by rules_go, 
# but we ensure the go_sdk is downloaded (from previous chapters).
```
#### 2. Create the Language Targets (`src/proto/BUILD.bazel`):
Append these rules to the file you created in step 4.1.

```
# src/proto/BUILD.bazel

load("@rules_cc//cc:defs.bzl", "cc_proto_library")
load("@rules_go//proto:def.bzl", "go_proto_library")
load("@grpc//bazel:cc_grpc_library.bzl", "cc_grpc_library")

# --- C++ Generation ---

# Generates greeter.pb.h and greeter.pb.cc (Messages)
cc_proto_library(
    name = "greeter_cc_proto",
    deps = [":greeter_proto"],
)

# Generates greeter.grpc.pb.h and greeter.grpc.pb.cc (Service Stub)
cc_grpc_library(
    name = "greeter_cc_grpc",
    srcs = [":greeter_proto"],
    deps = [":greeter_cc_proto"], 
    visibility = ["//visibility:public"],
)

# --- Go Generation ---

# Generates greeter.pb.go and greeter_grpc.pb.go
go_proto_library(
    name = "greeter_go_proto",
    compilers = ["@rules_go//proto:go_grpc"], # This plugin enables gRPC generation
    importpath = "bazel-reference/04/src/proto",
    proto = ":greeter_proto",
    visibility = ["//visibility:public"],
)
```
## 4.3 Cross-Language Integration
Now comes the magic. We will build a C++ Server and a Go Client. They will communicate using the code generated by Bazel from the same `.proto` file.

### Practical: C++ Server & Go Client
#### 1. The C++ Server (`src/server_cpp/`)

- File: `src/server_cpp/server.cc`

```c++
#include <iostream>
#include <memory>
#include <string>

#include <grpcpp/grpcpp.h>
#include "src/proto/greeter.grpc.pb.h" // Generated by Bazel!

using grpc::Server;
using grpc::ServerBuilder;
using grpc::ServerContext;
using greeter::Greeter;
using greeter::HelloRequest;
using greeter::HelloReply;

class GreeterServiceImpl final : public Greeter::Service {
    grpc::Status SayHello(ServerContext* context, const HelloRequest* request,
                          HelloReply* reply) override {
        std::string prefix("Hello from C++ Server, ");
        reply->set_message(prefix + request->name());
        return grpc::Status::OK;
    }
};

void RunServer() {
    std::string server_address("0.0.0.0:50051");
    GreeterServiceImpl service;

    ServerBuilder builder;
    builder.AddListeningPort(server_address, grpc::InsecureServerCredentials());
    builder.RegisterService(&service);
    std::unique_ptr<Server> server(builder.BuildAndStart());
    std::cout << "Server listening on " << server_address << std::endl;
    server->Wait();
}

int main() {
    RunServer();
    return 0;
}
```
- File: src/server_cpp/BUILD.bazel

```
cc_binary(
    name = "server",
    srcs = ["server.cc"],
    deps = [
        "//src/proto:greeter_cc_grpc", # Our generated gRPC lib
        "@grpc//:grpc++",               # The gRPC runtime
    ],
)
```
#### 2. The Go Client (`src/client_go/`)

- File: `src/client_go/main.go`

```go
package main

import (
    "context"
    "log"
    "time"

    pb "github.com/myuser/myproject/src/proto" // Corresponds to go_proto_library importpath
    "google.golang.org/grpc"
    "google.golang.org/grpc/credentials/insecure"
)

func main() {
    conn, err := grpc.NewClient("localhost:50051", grpc.WithTransportCredentials(insecure.NewCredentials()))
    if err != nil {
        log.Fatalf("did not connect: %v", err)
    }
    defer conn.Close()
    c := pb.NewGreeterClient(conn)

    ctx, cancel := context.WithTimeout(context.Background(), time.Second)
    defer cancel()

    r, err := c.SayHello(ctx, &pb.HelloRequest{Name: "Bazel User"})
    if err != nil {
        log.Fatalf("could not greet: %v", err)
    }
    log.Printf("Response: %s", r.GetMessage())
}
```
- File: `src/client_go/BUILD.bazel` Note: You can let Gazelle generate this, or write it manually:

```
load("@rules_go//go:def.bzl", "go_binary", "go_library")

go_binary(
    name = "client",
    srcs = ["main.go"],
    deps = [
        "//src/proto:greeter_go_proto", # Generated Go code
        "@org_golang_google_grpc//:go_default_library",
        "@org_golang_google_grpc//credentials/insecure:go_default_library",
    ],
)
```
#### 3. Run the Integration

You will need two terminal windows.

Terminal 1 (Start the Server):

```bash
bazel run //src/server_cpp:server
```
Expected Output: `Server listening on 0.0.0.0:50051`

Terminal 2 (Run the Client):

```bash
bazel run //src/client_go:client
```
Expected Output: `Response: Hello from C++ Server, Bazel User`

Summary: You defined the protocol once. Bazel generated the C++ server stubs and the Go client struct automatically. If you change the `.proto` file, Bazel will rebuild both apps to match the new definition.
