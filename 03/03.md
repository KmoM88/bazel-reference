# Chapter 3: Polyglot Builds: Language Specifics
Bazel excels at building projects that use multiple programming languages (polyglot monorepos). This chapter covers the specific rules and tools required for C++, Go, and Python.

## 3.1 C++ Development (`rules_cc`)
C++ rules are often built-in or provided via the core Bazel distribution, though they are technically part of the `rules_cc` set. They manage compilation and linking across multiple platforms.

- Core Rules:
	- `cc_library`: Used for compiling source files (`.cc`, `.cpp`) into a reusable library (static or shared).
	- `cc_binary`: Produces a final executable application.
	- `cc_test`: Creates an executable for running C++ tests.
	- `cc_import`: Used to incorporate pre-compiled C++ libraries (e.g., vendor binaries) into the Bazel dependency graph.

- Managing Headers and Includes:
	- `hdrs`: Specifies the header files (`.h`, `.hpp`) that are exported by the library and are visible to consumers of this target.
	- `includes`: Used when the source files in the library need to include headers using paths relative to the current directory, rather than relative to the workspace root.
	- `strip_include_prefix`: Essential for making header inclusion paths clean. It tells Bazel to remove a prefix from the path when making headers available to other targets.

	Example: If your headers are in `src/foo/include/bar.h`, you might use `strip_include_prefix = "src/foo/include"`. Consumers then only need to `#include "bar.h"`.

- Linking External System Libraries: To use system-installed libraries (like `libssl` or `libpthread`) that are not managed by Bazel, you use the `cc_library` rule with the `linkopts` attribute:

```
cc_library(
    name = "system_ssl",
    linkopts = ["-lssl", "-lcrypto"],  # Tells the linker to include these libraries
    # Important: This breaks hermeticity and should be avoided when possible.
)
```
### Practical: Building C++
Let's build a simple C++ binary that depends on a custom library.

#### 1. Prerequisites

Ensure a C++ compiler (GCC or Clang) is installed on your system. Bazel will auto-detect it.

#### 2. Project Structure & Source Code Create the following files inside your workspace:

- `src/cpp_tutorial/hello.h`:

```c++
#pragma once
void print_hello();
```
- `src/cpp_tutorial/hello.cc`:
```c++
#include "hello.h"
#include <iostream>
void print_hello() {
    std::cout << "Hello from C++ Library!" << std::endl;
}
```
- `src/cpp_tutorial/main.cc`:

```c++
#include "hello.h"
int main() {
    print_hello();
    return 0;
}
```
#### 3. Bazel Configuration Create `src/cpp_tutorial/BUILD.bazel`:

```
# src/cpp_tutorial/BUILD.bazel

cc_library(
    name = "hello_lib",
    srcs = ["hello.cc"],
    hdrs = ["hello.h"],
)

cc_binary(
    name = "hello_world",
    srcs = ["main.cc"],
    deps = [":hello_lib"], # Links the library above
)
```
### 4. Build & Run:

```bash
bazel run //src/cpp_tutorial:hello_world
```
Expected Output: Bazel will compile the objects, link them, and execute the binary.
```
INFO: Analyzed target //src/cpp_tutorial:hello_world ...
...
Hello from C++ Library!
```
## 3.2 Go Development (`rules_go` & Gazelle)
Go development in Bazel relies on the `rules_go` module and an essential companion tool called Gazelle.
- Setup: You must have declared `rules_go` in your `MODULE.bazel` file (Chapter 2).
- The Ecosystem: Why you need Gazelle:
	- Unlike Bazel's native rules, Go's external dependency management (using `go.mod`) and package structure do not map perfectly to Bazel's BUILD file requirements.
	- Gazelle is a build file generator that scans your Go source code (import statements and `go.mod`) and automatically generates or updates the necessary `BUILD.bazel` files.
	- This keeps maintenance low, as developers can focus on Go imports, and Gazelle ensures the Bazel dependency graph is correct.

- Core Rules:
	- `go_library`: Defines reusable Go code.
	- `go_binary`: Produces a final executable.
	- `go_test`: Defines tests for a package.

- Generating BUILD files automatically:
	1. Install Gazelle (usually via Bazel itself).
	2. Run `bazel run //:gazelle` (or similar configured target) from the workspace root.
	3. Gazelle creates or updates all `BUILD.bazel` files containing `go_library`, `go_binary`, and dependency declarations.

### Practical: Building Go with Gazelle
We will configure Gazelle to automatically generate the build file for a simple Go app.

#### 1. Prerequisites

Go SDK installed locally (for `go mod` commands).

#### 2. Configure MODULE.bazel
Update your `MODULE.bazel` to register the Go toolchain and Gazelle extension:

```
# MODULE.bazel
bazel_dep(name = "rules_go", version = "0.50.1")
bazel_dep(name = "gazelle", version = "0.39.1")

go_sdk = use_extension("@rules_go//go:extensions.bzl", "go_sdk")
go_sdk.download(version = "1.22.0") # Downloads hermetic Go SDK

gazelle = use_extension("@gazelle//:extensions.bzl", "gazelle")
gazelle.go_deps(
    path = "go.mod",
    prune = True,
    go_mod = "//:go.mod",
)
```
#### 3. Source Code Initialize a Go module and create a simple file:

```bash
# In workspace root
go mod init bazel-reference/03
mkdir -p src/go_tutorial
```
- `src/go_tutorial/main.go`:

```go
package main
import "fmt"
func main() {
    fmt.Println("Hello from Go!")
}
```
#### 4. Setup Gazelle Target
Create a `BUILD.bazel` in the root of your workspace to define the Gazelle runner:

```
# BUILD.bazel (Root)
load("@gazelle//:def.bzl", "gazelle")

# This target runs the tool to generate other BUILD files
gazelle(name = "gazelle")
```
#### 5. Build & Run
First, ask Gazelle to generate the BUILD file for your Go code:
```bash
bazel run //:gazelle
```
Check `src/go_tutorial/`: You will see a new `BUILD.bazel` file appeared automatically.

Now, run the code:

```bash
bazel run //src/go_tutorial:go_tutorial
```
Expected Output:
```
Hello from Go!
```
## 3.3 Python Development (`rules_python`)
Building Python applications with Bazel requires managing interpreters and external package dependencies (`pip`).
- Setup: You must have declared `rules_python` in your `MODULE.bazel` file.
- Core Rules:
	- `py_library`: Defines reusable Python modules.
	- `py_binary`: Produces a hermetic entry point for running your application.
	- `py_test`: Runs tests using a specified Python toolchain.
- Managing Pip Dependencies (`pip.parse` extension):
	- External Python packages are managed through a Bazel module extension provided by `rules_python`.
	- You specify your required packages and versions (similar to a `requirements.txt`) directly in the `MODULE.bazel` file or an external `.json` file, which is then processed by the pip.parse extension.
	- This extension downloads the packages and creates Bazel targets for each one, making them available as dependencies.
- Creating Hermetic Python Toolchains:
	- Hermeticity in Python means ensuring the exact same interpreter and standard libraries are used everywhere.
	- `rules_python` allows defining custom toolchains that point to a controlled Python environment (e.g., a specific Python 3.11 build).
	- This ensures that the build output is independent of the Python version installed on the developer's host machine.

### Practical: Hermetic Python
We will run a Python script that uses a strict toolchain managed by Bazel.

#### 1. Prerequisites

- None (Bazel will download a hermetic Python interpreter).

#### 2. Configure MODULE.bazel
Update `MODULE.bazel` to register the Python toolchain:

```
# MODULE.bazel
bazel_dep(name = "rules_python", version = "0.31.0")

python = use_extension("@rules_python//python/extensions:python.bzl", "python")
python.toolchain(
    python_version = "3.11", # We force Python 3.11 regardless of what is on your OS
)
```
#### 3. Source Code
Create `src/py_tutorial/main.py`:

```python
import sys

def main():
    print(f"Hello from Python running on version: {sys.version}")

if __name__ == "__main__":
    main()
```
#### 4. Bazel Configuration
Create `src/py_tutorial/BUILD.bazel`:

```
# src/py_tutorial/BUILD.bazel
load("@rules_python//python:defs.bzl", "py_binary")

py_binary(
    name = "py_hello",
    srcs = ["main.py"],
    main = "main.py",
)
```
#### 5. Build & Run
Run the python binary:

```bash
bazel run //src/py_tutorial:py_hello
```
Expected Output: Bazel will download a standalone Python 3.11 
interpreter and run your script with it.
```
Hello from Python running on version: 3.11.x ...
```
