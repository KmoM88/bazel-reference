# Chapter 1: Foundations & Philosophy (Bazelisk & Versioning)
## 1.1 The Bazel Philosophy
Bazel is a powerful open-source build and test tool developed by Google. It focuses on achieving fast, correct, and reliable builds through three core principles:

- Hermeticity (Airtight Builds): A build is hermetic if it is guaranteed to produce the same output given the same inputs, regardless of the environment (machine, user, current time, etc.). Bazel enforces this by ensuring build actions only access declared inputs, isolating them from the external environment (like system-wide compilers or environment variables).
- Reproducibility: A direct result of hermeticity. If the build environment is fully defined, the build will be the same everywhere.
- Scalability: Bazel is designed to handle extremely large code bases (monorepos) by leveraging high degrees of parallelism and sophisticated caching.

## 1.2 Architecture: The Client-Server Model
Bazel operates using a client-server model for speed and efficiency:
1. A user runs a Bazel command (the client, e.g., `bazel build //...`).
2. The client starts or connects to a running Bazel Server (the JVM process) that stays alive in the background.
3. The Server handles the actual heavy lifting, including caching, parallel execution, and disk I/O. This avoids the overhead of starting a new JVM for every command, making subsequent builds much faster.

## 1.3 Environment Setup (The Right Way)
### Installing Bazelisk
To ensure stability and reproducibility across teams, you should use Bazelisk, the official launcher for Bazel.
- What is Bazelisk? It's a smart wrapper that automatically finds and downloads the correct Bazel binary specified in your project's `.bazelversion` file.
- Why use Bazelisk? It guarantees that every developer and every CI/CD pipeline is using the exact same version of Bazel specified by the project, preventing "works on my machine" issues related to tool version skew.

DO NOT install Bazel directly via system package managers (like apt or brew install bazel). Always install Bazelisk and let it manage the Bazel binary.

## 1.4 Version Management
Version control in Bazel is achieved by pinning the desired version in the project root:
- Creating the `.bazelversion` file: This plain text file in the root of your repository tells Bazelisk which version to use.
- Pinning a specific version:
```
# .bazelversion
7.7.1
```
When a user runs `bazel build` (via Bazelisk), Bazelisk reads `8.0.0`, downloads that specific binary if needed, and runs the command with it.

## 1.5 Core Terminology
| Term | Definition | Example |
|------|------------|---------|
| Workspace | The root directory of your project, defined by the presence of a `MODULE.bazel` file. | The root of your Git repository. |
| Module | The modern way to define a Bazel project and manage its external dependencies (supersedes the old `WORKSPACE` file). | Defined by the `MODULE.bazel` file. |
| Package | A directory containing a `BUILD.bazel` file. Targets within a package can reference each other. | `//src/app/` |
| Target | An object defined in a `BUILD.bazel` file that represents something Bazel can build (a library, binary, or test). | `//src/app:main_binary` |
| Rule | A blueprint for creating targets (e.g., `cc_library`, `py_binary`). Rules specify the required inputs and the action to be executed. | `cc_library(name = "util")` |
| Label | The unique, canonical identifier for a target. | `//path/to/package:target_name` |
| Action | A low-level operation performed during the build (e.g., running GCC, compressing a file). | Compiling a single `.cpp` file to an object file. |

## 1.6 Project Structure (Bzlmod Focus)
Every Bazel project is defined by a specific set of configuration files at the root level:

| File Name | Purpose | Example Content |
|-----------|---------|-----------------|
| `.bazelversion` | Mandatory. Pins the Bazel version used by Bazelisk. | `8.0.0` |
| `MODULE.bazel` | Mandatory. Defines the current module's name and its external dependencies (Bzlmod). This replaces the old `WORKSPACE` file. | `module(name = "my_project")` |
| `BUILD.bazel` | Defines targets (libraries, binaries) and their dependencies within a package. | `cc_binary(name = "hello", srcs = ["hello.cc"])` |
| `.bazelrc` | Optional. Stores flags and build settings specific to the repository (e.g., remote caching configuration). | `build --copt=-O2` |
